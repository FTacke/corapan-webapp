# Legacy archive and restore

Since 2026-10-19 the corpus data, historical states and processing evidence of this repository are archived outside the
checkout. The local checkout keeps the software, the documentation and the data the local web application and the
maintenance scripts need (`media/transcripts`, `data/blacklab/index`, `data/blacklab/export/tsv` and `export/metadata`,
`data/public`, `data/db/public`). The production server is not affected; it keeps its own copies.

The archived tree mirrors the repository layout: a file `<path>` of this checkout is archived at `<tree>\<path>`. Its
`ARCHIVE_MANIFEST.json` lists every file with size and SHA-256; the tree is write-once and is never changed. The file lists
of what was archived are `docs/agent-runs/2026-10-19_legacy_retention_manifest.csv` and
`docs/agent-runs/2026-10-19_legacy_retention_supplement_manifest.csv`.

Contents of the tree:

- `media/mp3-full/` – the 146 original recordings (byte-identical to Zenodo v3/v4)
- `media/transcripts/` – the transcripts, annotation v3.2 (= Zenodo v4), incl. the editor log
- `maintenance_pipelines/_0_json/backups/pre-v3_1-transcripts/` – annotation state of Zenodo v3
- `maintenance_pipelines/_0_json/backups/pre-tense-schema-migration/` – the v3.1 intermediate state (not on Zenodo)
- `maintenance_pipelines/_0_json/backups/{manual-repairs,smoke-tests,multicountry-smoke}/` – repair and test intermediate states
- `data/blacklab/{index,export,backups,quarantine}/` – the current index, its TSV/metadata export and historical index builds
- `data/exports/tsv/` – an older export format (Nov. 2025)
- `data/public/`, `data/db/public/` – public metadata, statistics, SQLite statistics databases
- processing evidence and release records (`maintenance_pipelines/_0_json/{docs,logs,results,state,tools}`, `_1_zenodo-repos/releases`, `docs/agent-runs`)

Not archived: the development PostgreSQL data under `data/db/restricted/` (local only; may contain account data).

## Restore for local work

Read-only copy from the archive (or the backup) into the checkout, for example the full audio:

```powershell
$tree = '\\dfs.hrz.uni-marburg.de\PROJEKTE\FB10\TACKE_FORSCHUNGSDATEN\projects\panhispanic_media_corpora\legacy\corapan\corapan'
robocopy "$tree\media\mp3-full" "media\mp3-full" /E /COPY:DAT
```

Never write into the archive tree. Check restored files against `ARCHIVE_MANIFEST.json` (SHA-256).

- Without `media/mp3-full` the local player has no audio; search, transcripts and the editor work.
- `media/mp3-split` is not archived: it is regenerable with `maintenance_pipelines/_0_mp3/mp3_prepare_and_split.py`
  (4-minute chunks, 30 s overlap); without it, audio snippets are cut from the full files.
- `data/blacklab/export/tsv/tsv_for_index/` is generated by `app/scripts/blacklab/build_blacklab_index.ps1` from `export/tsv`.
- Before a BlackLab publish, copy `data/blacklab/index` to `data/blacklab/quarantine/index.build`.

## Readers in the CO.RA.PAN repository

CO.RA.PAN (v3) reads this checkout through the named root `CORAPAN_LEGACY_ROOT` (`config/corpus_paths.yml`:
`media/transcripts`, `media/mp3-full`, `media/mp3-split`). Because the tree mirrors the layout, pointing that variable at the
archived tree makes those readers read the archive instead (read-only). That switch is a configuration change in the CO.RA.PAN
repository and is made there.
